# RetailScope Power BI delivery kit

This folder is the source-controlled handoff for the UCI real-data report. It
contains the data contract, typed Power Query scripts, relationships, DAX,
theme, and a page-by-page visual specification. The analytical values are
generated by Python; report authors do not need to reimplement model logic in
Power BI.

## Included

| Asset | Purpose |
|---|---|
| [`model_contract.json`](model_contract.json) | Machine-readable tables, columns, relationships, measures, and visual bindings |
| [`queries/`](queries/) | One typed Power Query expression per imported table, plus the `DataRoot` parameter |
| [`real_measures.dax`](real_measures.dax) | Revenue, customer, risk, evaluation, and quality measures |
| [`retailscope_theme.json`](retailscope_theme.json) | Restrained report palette matching the repository preview |
| [`REPORT_SPEC.md`](REPORT_SPEC.md) | Four-page layout, visual roles, formatting, and accessibility rules |
| [`REAL_DATA_GUIDE.md`](REAL_DATA_GUIDE.md) | Model semantics and interpretation constraints |

The real pipeline writes eight import-ready CSVs to `outputs/real/marts/`:

```text
dim_customer             dim_product
dim_date                 fact_sales
customer_scores          cohort_retention
data_quality_metrics     model_metrics
```

## Build on Windows

### 1. Prepare and verify the marts

From PowerShell at the repository root:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\scripts\prepare_powerbi.ps1
```

The script verifies the official workbook, runs the real-data pipeline, checks
the unit tests, and validates every generated CSV header against
`model_contract.json`.

### 2. Import with the supplied queries

1. Open Power BI Desktop and create a blank report.
2. In Power Query, create a text parameter named `DataRoot` whose value is the
   absolute path to `outputs\real\marts`.
3. Create one blank query for each remaining file in [`queries/`](queries/),
   paste the expression into Advanced Editor, and use the filename as the query
   name.
4. Apply changes. All dates, identifiers, booleans, currency values, and ratios
   are typed in the supplied expressions.

### 3. Build the semantic model

Create these active, single-direction relationships:

| One side | Many side |
|---|---|
| `dim_customer[customer_id]` | `fact_sales[customer_id]` |
| `dim_product[product_id]` | `fact_sales[product_id]` |
| `dim_date[date]` | `fact_sales[event_date]` |
| `dim_customer[customer_id]` | `customer_scores[customer_id]` |

Mark `dim_date[date]` as the date table. Keep `customer_scores[snapshot_date]`
disconnected from the transaction date: it is a scoring cutoff, not a sale
date. Keep `cohort_retention`, `data_quality_metrics`, and `model_metrics`
disconnected.

Add every definition in [`real_measures.dax`](real_measures.dax) as a separate
measure. Format GBP measures as currency, risk/rate measures as percentages,
and lift as `0.00×`.

### 4. Apply the report design

Import [`retailscope_theme.json`](retailscope_theme.json) from **View → Themes →
Browse for themes**, then implement the four pages in
[`REPORT_SPEC.md`](REPORT_SPEC.md). Use a single-select snapshot slicer on all
score-based pages.

### 5. Save and validate

Save locally as `RetailScope.pbix`, or enable the Power BI Project preview and
save as PBIP for text-based version control. Refresh once, inspect every page,
and complete the acceptance checks in the report specification.

## Automated package check

The repository CI validates the source package without Power BI Desktop:

```bash
python scripts/validate_powerbi_contract.py
python scripts/validate_powerbi_contract.py --data-root outputs/real/marts
```

The first command checks package structure, relationship references, DAX names,
theme JSON, and visual bindings. The second also verifies every generated CSV
header and order.

## Why there is no committed `.pbix`

Microsoft supports PBIX/PBIP conversion only through Power BI Desktop. This
repository is built and tested on Linux, where Desktop is unavailable. A binary
created or claimed without opening and refreshing it in Desktop would not be a
verifiable deliverable, so the repository commits the reviewable authoring
sources and keeps the final Desktop save as an explicit Windows acceptance
step.
